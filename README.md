# Affaires sensibles — catalogue des épisodes

Scrapes the metadata of every episode of the France Inter podcast
[Affaires sensibles](https://www.radiofrance.fr/franceinter/podcasts/affaires-sensibles)
and publishes a small static site to browse them:
**<https://thomzoy.github.io/affaires_sensibles/>**

The site (in French) lets you:

- browse the series ("Crimes et manigances au siècle des Lumières", …) and their episodes in order
- list all episodes, filtered by one or more themes (OR) and a date range, sorted by date or in random order
- search titles and descriptions (accent- and case-insensitive)
- open a random episode
- play an episode in the page, open it on radiofrance.fr, or open it in the Radio France mobile app

## Project layout

```
main.py              scraper: episode list (+ episode details with --details)
build_site.py        turns the scraped data into docs/episodes.json for the site
data/
  episodes.json      one entry per broadcast (raw scrape output)
  episodes.csv       same, as CSV
  details_cache.jsonl  per-episode details, one JSON object per line
docs/                the static site served by GitHub Pages
  index.html, app.js, style.css
  episodes.json      generated by build_site.py
.github/workflows/publish.yml   daily scrape + build + deploy
```

## Usage

Requires [uv](https://docs.astral.sh/uv/).

```bash
uv run main.py             # episode list only (~1 min)
uv run main.py --details   # + summary, audio URL, guests, themes, series for each episode
uv run build_site.py       # writes docs/episodes.json
python3 -m http.server -d docs   # preview at http://localhost:8000
```

`--delay` sets the pause between requests (default 0.5 s).

## How it works

### Data source

Radio France doesn't offer a public API for this. The site is built with SvelteKit, and every page has a
data route: append `/__data.json` to its URL.

- Episode list: `https://www.radiofrance.fr/franceinter/podcasts/affaires-sensibles/__data.json?p=N`
  (20 episodes per page, newest first; page 1 must be requested **without** `?p=1`, which returns a redirect)
- Episode page: `https://www.radiofrance.fr/<episode path>/__data.json`

The responses use SvelteKit's "devalue" format: `data` is one flat array, and objects refer to other
entries by their index. `decode_devalue()` in `main.py` rebuilds the normal object tree.

The RSS feed (`radiofrance-podcast.net/podcast09/podcast_0b91efaf-….xml`) is simpler but only goes back a
few months, so it isn't used.

### Episode list

`content.expressionCount` on the first page gives the total number of entries (3,553 at the time of
writing), which determines the number of pages to fetch. Requesting a page past the end silently returns
page 1 again, so the scraper also stops when a page brings no new entries.

**Rebroadcasts:** an episode that airs again appears again in the list, with the same id but a later
date. `expressionCount` counts broadcasts, not episodes. The scraper keeps every broadcast, identified by
`(id, start date)`, and adds an `is_rebroadcast` column (true for every airing except the first). That's
why `data/episodes.csv` has ~3,550 rows for ~2,840 distinct episodes.

List fields: `id`, `title`, `url`, `path`, `published_date`, `start_date`, `end_date`, `duration_s`,
`is_expired`, `is_timeshiftable`, `image_url`, `image_legend`, `image_copyright`, `is_rebroadcast`.

### Episode details (`--details`)

The list doesn't include descriptions, so `--details` fetches each episode page once (per id, not per
broadcast) and reads:

| Field | Source in the page data |
|---|---|
| `summary` | `content.chapo` |
| `audio_url` | `content.manifestation.url` |
| `producers`, `guests`, `guest_roles` | `content.producers`, `content.guest` |
| `themes` | `content.themes` |
| `serie_id`, `serie_title`, `serie_url` | `content.series[0]` |
| `serie_episode`, `serie_episode_count` | parsed from `content.seo.title` ("… épisode 1/6 du podcast …") |

Results are appended to `data/details_cache.jsonl` as they come, so an interrupted run resumes where it
stopped and later runs only fetch new episodes. A full run from scratch takes ~30 minutes. Episodes
without a page (a few dozen old ones) have no details.

### Site data (`build_site.py`)

Merges `data/episodes.json` with the details cache, keeps **one entry per episode** dated by its first
broadcast, and writes a compact `docs/episodes.json` (~2 MB) with the fields the site needs.

### Static site (`docs/`)

Plain HTML/CSS/JavaScript, no build step. The only dependency is [Plyr](https://plyr.io), loaded from
jsDelivr, which draws the audio player (iOS Safari's native player gets clipped). `app.js` loads `episodes.json` once and
does everything client-side:

- **Routing** uses the URL hash, so the back button and shared links work:
  `#/` (series), `#/serie/<id>`, `#/episode/<id>`, `#/episodes?theme=…&du=…&au=…&tri=…`, `#/recherche/<query>`
- **Long lists** are rendered 50 cards at a time and extended as you scroll (an `IntersectionObserver`
  watches a marker at the bottom); rendering all ~2,800 cards at once froze the page on phones.
  Thumbnails use `loading="lazy"` and Radio France's image service sizes (`<image url>/200x200`, …).
- **Opening in the Radio France app** (shown on iOS and Android only) uses the same deep link as the
  "Ouvrir dans l'App" button on radiofrance.fr: `radiofrance://radiofrance.fr/layout?id=<episode id>`.
  If the app hasn't opened after 2.5 s, the page falls back to the episode on radiofrance.fr.

## Deployment

`.github/workflows/publish.yml` runs daily at 05:00 UTC, on every push to `master`, and on demand
(Actions tab → "Run workflow"). It runs `main.py --details`, then `build_site.py`, and deploys `docs/` to
GitHub Pages.

`data/details_cache.jsonl` is committed and also kept in the GitHub Actions cache. The cache is restored on
top of the committed file when it exists; on the first run (no cache yet) the committed file is used as
is, so only new episodes are fetched. The cache is saved even when a run fails.

One-time repository setup:

1. Settings → Pages → Source: **GitHub Actions**
2. Settings → Environments → `github-pages` → allow deployments from `master`
   (GitHub may default this to `main` only)

## Caveats

- `__data.json` is an internal route of radiofrance.fr, not a public API: it may change or break without
  notice. Requests are spaced out to stay polite.
- Themes, descriptions and series only exist for episodes whose details were fetched.
- The app deep link was taken from radiofrance.fr's own code; it hasn't been tested on every device.
